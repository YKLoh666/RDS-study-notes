b)

i)

- All transactions are processed sequentially on a single chain, no parallel processing, which limits the number of transactions that can be processed per second.
- Single chain architecture requires all nodes to validate and store all transactions, which increases the storage and processing requirements for each node, leading to slower transaction processing times and higher fees.
- The single chain architecture also limits the ability to scale horizontally, as adding more nodes does not increase the transaction throughput, and can lead to network congestion and delays in transaction processing.

ii) Sharding is considered Layer 1 scaling solution because it involves changes to the main blockchain protocol itself, rather than being built on top of the existing blockchain as a separate layer. It requires modifications to the consensus mechanism and data structure of the blockchain to enable parallel processing of transactions across multiple shards, which is a fundamental change to the underlying blockchain architecture.

iii)

- Sharding works by partitioning the blockchain network into smaller groups of nodes called shards, each of which can process its own transactions and smart contracts independently.
- Each shard maintains its own state and transaction history, and can communicate with other shards through a cross-shard communication protocol.
- It allows for parallel processing of transactions across multiple shards, which increases the overall throughput and scalability of the blockchain network.
- It reduces network congestion by improving network wide consensus efficiency, as each shard has its own consensus committee that validates transactions within the shard, rather than requiring all nodes to validate all transactions on the main chain.

iv) 

- Yes, I agree. Sharding increases network capacity by allowing parallel processing of transactions across multiple shards, which improves the overall throughput and scalability of the blockchain network.
- Each shard has its own consensus committee that validates transactions within the shard, which reduces the workload on individual nodes and allows for more efficient processing of transactions.
- This approach maintains decentralisation, as each shard is still composed of a group of nodes that participate in the consensus process, and security is maintained through cryptographic techniques and cross-shard communication protocols that ensure the integrity and authenticity of transactions across shards.
